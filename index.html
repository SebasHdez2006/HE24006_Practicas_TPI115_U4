Preguntas y Conclusiones del Laboratorio

1. ¿A partir del ejemplo 1 y ejercicios desarrollados hasta el momento qué puede concluir?
Puedo concluir que XML es extremadamente flexible ya que nos permite inventar y anidar nuestras propias etiquetas sin depender de un estándar estricto previo. Siempre que respetemos las reglas de documento "bien formado" (etiquetas de apertura y cierre correctas, anidamiento lógico), los datos quedan perfectamente estructurados y jerarquizados.
2. ¿A partir del ejemplo 2 y ejercicios desarrollados hasta el momento qué puede concluir?
Se concluye que el diseño de un documento XML requiere un análisis lógico. Es vital distinguir qué información debe ir como un atributo (datos simples que describen al elemento, como el ID o la moneda general de un país) y qué información debe ir como un elemento hijo, asegurando que la jerarquía refleje la realidad conceptual de los datos.
3. ¿A partir de los ejercicios desarrollados en esta sección II.3 (Conversión a JSON) qué puede concluir?
Concluyo que JSON es una alternativa mucho más ligera y compacta para el intercambio de datos. Al realizar la conversión online, los elementos XML se transforman eficientemente en pares de "clave: valor", demostrando que JSON es más directo de leer para las máquinas, aunque XML ofrece una semántica más robusta a través de sus atributos.
4. ¿A partir de los ejercicios de CSS desarrollados, qué puede concluir?
Se concluye que las hojas de estilo en cascada (CSS) son esenciales para dotar de presentación visual a un documento de datos puro como XML. Mediante propiedades como 'display' podemos controlar el flujo visual, y usando selectores avanzados de CSS3 logramos superar la limitación natural de XML de no mostrar sus atributos en pantalla.
