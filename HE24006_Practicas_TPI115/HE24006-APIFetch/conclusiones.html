Flujo de una petición con Fetch

  1. Se invoca fetch(url, opciones); el método devuelve una promesa que representa la petición HTTP.
  2. El primer then recibe un objeto Response. Antes de leer el cuerpo se comprueban response.ok o response.status.
  3. Según el tipo de recurso, se transforma el cuerpo con métodos como response.text(), response.json(), response.blob() o response.formData().
  4. El siguiente then recibe los datos ya convertidos y los usa para actualizar el DOM.
  5. Un catch maneja errores de red o los errores lanzados al validar la respuesta HTTP.

Conclusiones

  1. Fetch ofrece una forma moderna y legible de realizar solicitudes asíncronas mediante promesas, lo cual facilita encadenar la recepción, conversión y presentación de datos.
  2. Los ejemplos demostraron que la misma estructura de Fetch permite recuperar texto, insertar HTML y procesar datos XML o JSON, cambiando únicamente el método que interpreta la respuesta.
  3. Una respuesta HTTP como 404 no activa por sí sola catch; por eso es indispensable revisar response.ok o response.status y lanzar un error cuando la respuesta no sea satisfactoria.
  4. Al ejecutarse desde un servidor web, Fetch respeta las reglas de origen y permite trabajar correctamente con archivos locales del proyecto sin depender de una recarga completa de la página.
