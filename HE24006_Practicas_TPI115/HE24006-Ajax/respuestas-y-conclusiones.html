Respuestas y conclusiones sobre AJAX

David Sebastián Hernández Elías · HE24006 · Técnicas de Programación en Internet

Preguntas de análisis

  1. ¿Qué es AJAX? ¿Es una tecnología o una combinación de tecnologías?
    AJAX significa Asynchronous JavaScript and XML. Es una técnica de desarrollo web y una combinación de JavaScript, DOM, HTTP, HTML/CSS y formatos de intercambio como texto, XML o JSON. Permite solicitar y procesar datos sin recargar por completo la página.
  2. ¿Qué es XMLHttpRequest y qué papel juega dentro de AJAX?
    Es una API del navegador representada por un objeto JavaScript. Permite crear solicitudes HTTP, enviar datos y recibir respuestas de manera asíncrona o síncrona. En AJAX es el mecanismo clásico que comunica la página con el servidor.
  3. ¿Cuáles son las propiedades y métodos principales de XMLHttpRequest?
    Las propiedades más usadas son onreadystatechange, readyState, responseText, responseXML, response, responseType, status, statusText y timeout. Sus métodos habituales son open() para configurar la petición, send() para enviarla, setRequestHeader() para agregar cabeceras, getResponseHeader() y getAllResponseHeaders() para leer cabeceras, y abort() para cancelarla.
  4. ¿Cuáles son los valores de readyState?
    0 significa que la solicitud no se ha inicializado; 1, que se abrió y se estableció la conexión; 2, que se recibieron las cabeceras; 3, que la respuesta se está descargando; y 4, que la operación terminó y la respuesta está lista para procesarse.
  5. ¿Cuáles son los valores y el significado de status?
    status contiene el código HTTP devuelto por el servidor. Los códigos 1xx son informativos, 2xx indican éxito, 3xx redirección, 4xx un error de la solicitud del cliente y 5xx un error del servidor. En esta práctica, 200 indica éxito; también son frecuentes 201 (creado), 204 (sin contenido), 400 (solicitud inválida), 401 (no autenticado), 403 (prohibido), 404 (no encontrado) y 500 (error interno del servidor).
  6. ¿Cuál es el procedimiento para usar XMLHttpRequest?
    Se crea el objeto, se registra una función de respuesta —por ejemplo en onreadystatechange—, se configura la petición con open(método, URL, true), se definen cabeceras si hacen falta y se ejecuta send(). La función comprueba que readyState === 4 y un estado HTTP exitoso antes de usar la respuesta y actualizar el DOM.
  7. ¿Qué características permiten reconocer una página que usa AJAX?
    Su contenido cambia parcial y dinámicamente mientras la página permanece abierta: aparecen resultados de búsqueda, filtros, mensajes, notificaciones o datos de un formulario sin una recarga completa. En las herramientas de desarrollo se observan solicitudes Fetch/XHR realizadas después de la carga inicial.
  8. ¿Qué ventajas tiene AJAX frente al ciclo tradicional de petición-respuesta?
    Reduce transferencias innecesarias, permite actualizar solo el componente afectado, mejora la sensación de rapidez e interactividad y conserva el contexto del usuario. También separa mejor los datos que se solicitan del modo en que se muestran en la interfaz.
  9. ¿Qué sitios web usan AJAX?
    Ejemplos habituales son Gmail al cargar correos y cambiar etiquetas, Google Maps al mover y buscar en el mapa, GitHub al cargar incidencias o comentarios dinámicamente y YouTube al mostrar sugerencias, comentarios o resultados de búsqueda sin una recarga completa.
  10. Liste cinco aplicaciones o casos de uso para AJAX.
    (1) autocompletado de búsquedas, (2) filtros de un catálogo de productos, (3) validación de campos de formulario mientras se escriben, (4) actualización de mensajes y notificaciones, y (5) paneles que consultan métricas o datos de seguimiento periódicamente.

Conclusiones

  1. AJAX permite construir interfaces más ágiles porque actualiza regiones concretas del documento en lugar de recargar toda la página.
  2. La correcta validación de readyState y status evita procesar respuestas incompletas o fallidas.
  3. El formato de la respuesta determina cómo se procesa: responseText sirve para texto o HTML, responseXML para XML y JSON debe convertirse a un objeto JavaScript antes de recorrer sus datos.
  4. La práctica muestra que la comunicación asíncrona no sustituye la lógica de la interfaz: después de recibir los datos todavía es necesario validarlos y actualizar el DOM de forma clara y segura.
